# Задание для облачной сессии: аудит auto-shorts и трекер нового канала

Репозиторий — этот (`auto-shorts`). Отчёт по-русски. Видеокарты нет и не нужна. Сначала прочитать `CLAUDE.md`
целиком: там что живо (только `es`), что на паузе (`en`, `pt` — не включать) и как устроены секреты. Секреты и
токены в код, логи и PR не выводить. Один PR на обе части, в описании — вывод тестов.

## Часть A. Аудит живого канала `es`

1. Прогоны GitHub Actions за последние 30 дней (`gh run list`, `gh run view --log` где нужно): по каждому
   воркфлоу `es` и общим (prepare-batch, discover-niche, monthly-*, weekly-report, watchdog-es, token-health) —
   сколько запусков, сколько упало, причины падений (сгруппировать), среднее время. Отдельно — вышел ли ролик
   каждый день (сверить с `video_history_es.json` и сторожем).
2. Расходы: где видно — токены/стоимость Claude API на ролик, внешние API. Если в логах нет — так и написать,
   и предложить, куда дописать учёт (без изменения логики генерации).
3. Что по данным канала уже собрано (`dropoff_stats_es.json`, `hook_stats_es.json`, `tone_stats_es.json`,
   weekly-report): 5-10 выводов, что работает и что нет, с цифрами.
4. Починить то, что падает повторяемо, и очевидные хрупкие места (ретраи сети, таймауты, проверка входа), с
   офлайн-тестами в `tests/`. Логику контента (темы, сценарии, голос) без явной ошибки не менять — только
   предложения в отчёте. Существующие тесты не ломать.

## Часть B. Трекер статистики нового канала «малышка и щенок»

Новый англоязычный канал (серия шортсов про малышку и щенка, код генерации — в другом репозитории
`korovazzz9-jpg/AI`, `video_gen/ui/_cp77_series/baby01/shorts.json`: 40 завязок, у каждой `name`, `type`, `risk`).
Канала ещё нет — трекер должен быть готов к подключению, но выключен, пока нет токена.

1. Переиспользовать `src/youtube_auth.py`, `src/analytics.py`, `src/analytics_retention.py` (не дублировать
   код — вынести общее, если нужно). Отдельный канал = отдельный секрет, например `YT_TOKEN_BABY` (+ что ещё
   требует youtube_auth — перечислить в `docs/SETUP_BABY.md` пошагово: как получить токен и куда положить).
2. `src/track_baby.py`: раз в день забирает по всем роликам канала просмотры, лайки, комментарии, средний % и
   время досмотра, подписки с ролика, показы/CTR, если API даёт; пишет `stats/baby/daily.csv` (дописывать,
   без дублей за один день) и `stats/baby/videos.csv` (последнее состояние). Сопоставление ролика с завязкой —
   файл `stats/baby/mapping.csv` (video_id,name), заполняется вручную или по метке `#s:<name>` в описании ролика
   (предложить, какой способ проще).
3. `src/track_baby_report.py`: недельная сводка `stats/baby/weekly.md` — по типам завязок (`type` из shorts.json;
   файл-копия `stats/baby/shorts_types.csv` name,type,risk — положить в репозиторий, выгрузив из shorts.json
   AI-репозитория, если он доступен; если нет — оставить формат и пустой файл с шапкой): число роликов, медиана
   просмотров за 48 ч и 7 дней, средний досмотр, лучшие и худшие; рекомендация «какие типы снимать больше».
4. `.github/workflows/track-baby.yml`: по расписанию раз в день + `workflow_dispatch`; первым шагом проверка
   наличия секрета — если его нет, выходит успешно с сообщением «канал не подключён» (не падает). Коммит CSV
   обратно в репозиторий — как делают существующие воркфлоу (сверить с ними, включая защиту от гонок/конфликтов
   git, см. записи в CLAUDE.md про rerun и stale SHA).
5. Тесты `tests/test_track_baby.py` без сети: разбор ответа API (подменить клиент), дописывание CSV без
   дублей, сводка по типам на выдуманных данных, выход без секрета.
