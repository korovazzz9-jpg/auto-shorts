# Задание (репозиторий auto-shorts): планировщик выкладки Nora & Maple

`src/publish_baby.py` выкладывает ОДИН ролик канала Nora & Maple по команде (время МСК, «не для детей»,
containsSyntheticMedia, тег `s-<name>`, проверка, что токен от канала «Nora & Maple»). Данные — из соседнего
репозитория AI (`../AI/video_gen/ui/_cp77_series/baby01/`: `shorts.json`, `CHANNEL_PACK.md`, `batch/<name>.mp4`);
в облаке его может не быть — тесты строить на подставных файлах (переменная `AI_REPO` уже поддерживается).
Прочитать `publish_baby.py` целиком и `docs/SETUP_BABY.md`.

1. Режим пачки: `python publish_baby.py --plan FROM-TO --start "ГГГГ-ММ-ДД" [--dry]` — выпуски по `order` из
   `shorts.json` с FROM по TO, по одному в день с даты старта: будни 19:30 МСК, суббота и воскресенье 17:00 МСК.
   Если два соседних выпуска одного `type` — переставить следующий подходящий (другого типа) вперёд, порядок в
   остальном сохранять; напечатать итоговое расписание (дата, время, номер, name, type, название).
2. Уже выложенное не выкладывать повторно: вести `stats/baby/published.csv` (name, video_id, publish_at_utc, at) и
   перед загрузкой проверять и его, и список роликов канала (по тегу `s-<name>`, как `track_baby.py`). Отсутствующий
   ролик (`batch/<name>.mp4` нет) — пропустить с сообщением, остальные выкладывать.
3. `--dry` ничего не загружает и не пишет — только печатает тела запросов и расписание. Без `--dry` — перед
   загрузкой пачки печатает расписание и спрашивает подтверждение `y/N` в консоли (флаг `--yes` для
   неинтерактивного запуска).
4. Тесты `tests/test_publish_baby.py` без сети: разбор выпуска из CHANNEL_PACK.md, тело запроса (статус, теги,
   publishAt в UTC), расписание по будням/выходным, перестановка одинаковых типов, пропуск выложенного и
   отсутствующего, проверка чужого канала (подменный клиент), `--dry` ничего не пишет. Существующие тесты не
   ломать.
5. В `docs/SETUP_BABY.md` дописать раздел «Выкладка» — команды и что они делают.
