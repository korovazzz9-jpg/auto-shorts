# Подключение трекера канала «малышка и щенок»

Трекер уже лежит в репозитории и **выключен**: пока нет секрета `YT_TOKEN_BABY`, поток
`track-baby.yml` каждое утро выходит успешно со строкой «канал не подключён» и ничего не пишет.
Подключить его — значит один раз получить токен канала и положить его в секреты репозитория.

Что он делает после подключения:

* **раз в день** (крон 07:41 UTC; GitHub-крон может опоздать на пару часов — для статистики не страшно) снимает по всем роликам канала просмотры, лайки, комментарии,
  средний % и время досмотра, подписки с ролика, а также показы и CTR обложки, если
  YouTube Analytics API их отдаёт; пишет `stats/baby/daily.csv` (снимок дня)
  и `stats/baby/videos.csv` (последнее состояние);
* **по понедельникам** собирает `stats/baby/weekly.md` — сводку по типам завязок
  и рекомендацию, какие типы снимать больше.

Claude не тратит: работают только YouTube Data API и Analytics API, квоты уходит несколько единиц в день.

## 1. Канал

Канал заводится как отдельный канал (Brand Account) под тем же Google-аккаунтом, что ES
(youtube.com → аватар → «Переключить аккаунт» → «Создать канал»); отдельный Google-аккаунт
не нужен. Так же сделано для ES, см. `SETUP_ES.md`, шаг 1.

## 2. Свой OAuth-клиент (рекомендуется)

У Google предел — 50 живых refresh-токенов на пару «OAuth-клиент + аккаунт». Общий клиент уже
однажды вытеснял чужие токены (см. `CLAUDE.md`, «Свой OAuth-клиент на каждый канал»), поэтому
каналу лучше дать свой.

1. Google Cloud Console → тот же проект, где клиенты EN/ES/PT → **APIs & Services → Credentials →
   Create credentials → OAuth client ID**, тип **Desktop app**, имя, например, `auto-shorts baby`.
2. Проверить, что в проекте включены **YouTube Data API v3** и **YouTube Analytics API**
   (APIs & Services → Library). Второй нужен для досмотра, подписок, показов и CTR.
3. Скачать JSON клиента и положить в корень репозитория как **`client_secret_baby.json`**.
   В git он не попадёт: `client_secret*.json` уже в `.gitignore`.

Если этот шаг пропустить, скрипт из п. 3 возьмёт общий `client_secret.json`, а трекер в Actions —
общие `YT_CLIENT_ID`/`YT_CLIENT_SECRET`.

Проверьте, что экран согласия OAuth в статусе **In production**, а не Testing: в режиме
Testing refresh-токен живёт 7 дней. У действующих каналов он уже в production, если проект тот же.

## 3. Токен канала

Локально, из корня репозитория, с установленным и залогиненным `gh`:

```
py src/get_youtube_token.py baby
```

Откроется браузер: войти под тем же Google-аккаунтом и **выбрать канал «малышки и щенка»**,
а не ES и не EN. Токен привязан к выбранному каналу. Скрипт сам положит в `.env` и в секреты репозитория
через `gh secret set`:

| секрет | что это | обязателен |
|---|---|---|
| `YT_TOKEN_BABY` | refresh-токен канала | да |
| `YT_CLIENT_ID_BABY` | id своего OAuth-клиента (только если был `client_secret_baby.json`) | нет |
| `YT_CLIENT_SECRET_BABY` | секрет своего OAuth-клиента (там же) | нет |

Без `YT_CLIENT_*_BABY` используются общие `YT_CLIENT_ID`/`YT_CLIENT_SECRET`: они уже заведены.

Токен скрипт не печатает. Если `gh` не залогинен, он напишет «НЕ обновлён — вручную»:
тогда нужно открыть GitHub → репозиторий → **Settings → Secrets and variables → Actions → New
repository secret** и вставить значения из `.env` под теми же именами.

Токен выдаётся с теми же правами, что у остальных каналов (`youtube_auth.SCOPES`: загрузка,
чтение, субтитры, аналитика). Трекеру хватило бы чтения и аналитики, но с тем же набором токен
пригодится и для будущей выгрузки на канал. При обновлении токена у Google запрашиваются ровно
эти права, другой набор дал бы `invalid_scope`.

## 4. Проверка

GitHub → **Actions → Track Baby Channel Stats → Run workflow**, поставить галочку «Пересобрать и
weekly.md». В логе шага *Daily snapshot* должна быть строка `Канал: <название> — подписчиков …`.
Если название не то, значит в п. 3 был выбран другой канал: получите токен заново. После прогона
в `master` появится коммит `chore(stats): baby channel snapshot …` с файлами `stats/baby/`.

Локально то же самое (токен берётся из `.env`):

```
cd src
py track_baby.py
py track_baby_report.py
```

`CHANNEL` для трекера не выставлять: у канала нет конфига в `config.py`, токен и клиент
берутся по имени `baby`.

## 5. Какая завязка в каком ролике

Сводке по типам нужно знать, какая из 40 завязок снята в ролике. Имена завязок (`name`) —
в `stats/baby/shorts_types.csv`. Отметить ролик можно тремя способами (трекер понимает все):

1. **Тег `s-<name>` в ролике — рекомендую.** YouTube Studio → ролик → «Показать больше» →
   «Теги», например `s-serious_lecture`. Зритель тегов не видит, поле заполняется в том же
   окне, что название, трекер подхватывает тег сам и дописывает пару в `mapping.csv`.
   Так же ES хранит служебные метки (`topic-`, `hook-`).
2. `#s:<name>` в описании ролика. Тоже подхватывается сам, но видно зрителю — лишний мусор в описании.
3. Строка `video_id,name` в `stats/baby/mapping.csv` руками. Этот способ главнее меток и годится,
   чтобы исправить ошибку или разметить уже выложенное задним числом.

Ролики без метки попадают в сводку как «без метки» и перечисляются в конце `weekly.md`.
Метку с именем, которого нет в `shorts_types.csv`, трекер пишет в лог как ошибку.

## 6. Если список завязок изменился

`stats/baby/shorts_types.csv` — выгрузка `name,type,risk` из
`video_gen/ui/_cp77_series/baby01/shorts.json` репозитория `korovazzz9-jpg/AI` (40 завязок,
версия после поправок VERIFY.md, коммит `af26a06`). Если в `shorts.json` поменялись завязки,
выгрузить заново:

```
py -c "import json,csv,sys; d=sorted(json.load(open(sys.argv[1],encoding='utf-8')),key=lambda x:x['num']); w=csv.writer(open('stats/baby/shorts_types.csv','w',newline='',encoding='utf-8'),lineterminator='\n'); w.writerow(['name','type','risk']); [w.writerow([x['name'],x['type'],x['risk']]) for x in d]" ..\AI\video_gen\ui\_cp77_series\baby01\shorts.json
```

## 7. Выкладка

Ролики выкладывает `src/publish_baby.py`. Запускать из каталога `src`, токен тот же `YT_TOKEN_BABY` из `.env`.
Откуда что берётся (репозиторий AI рядом, `../AI`, или путь в переменной `AI_REPO`):

* ролик — `video_gen/ui/_cp77_series/baby01/batch/<name>.mp4`;
* название, описание и хэштеги — `CHANNEL_PACK.md`, блок `**N. …**`, где N — это `order` завязки из `shorts.json`.

Что ставится у каждого ролика:

* «не для детей»;
* `containsSyntheticMedia`;
* тег `s-<name>`, по нему трекер сам свяжет ролик с завязкой;
* язык en, категория «Животные».

Перед загрузкой скрипт проверяет, что токен выдан именно каналу «Nora & Maple». Если канал другой, ничего не выкладывается.

**Пачка по расписанию:**

```
py publish_baby.py --plan 11-40 --start 2026-10-01 --dry    показать расписание и тела запросов
py publish_baby.py --plan 11-40 --start 2026-10-01          выложить, спросив y/N
py publish_baby.py --plan 11-40 --start 2026-10-01 --yes    выложить без вопроса
```

* **Выпуски и время.** Берутся выпуски с номерами `order` с 11 по 40, по одному в день начиная с `--start`. В будни — в 19:30 МСК, в субботу и воскресенье — в 17:00 МСК. Ролики загружаются сразу, но остаются приватными до своего времени (`publishAt`).
* **Одинаковые типы.** Два выпуска одного типа (`type`) подряд не ставятся: следующий того же типа уступает место ближайшему выпуску другого типа, в остальном порядок сохраняется. Первый выпуск пачки сверяется с последним уже выложенным.
* **Что пропускается.** Скрипт сообщает о каждом пропуске и выкладывает остальное:
  * выпуск уже есть в `stats/baby/published.csv`;
  * выпуск уже есть на канале — ищется по тегу `s-<name>`, так же как в `track_baby.py`;
  * ролика `batch/<name>.mp4` нет.
* **Итоговое расписание** печатается: дата, день недели, время, номер, name, type, название. Без `--yes` после него скрипт спрашивает y/N.
* **Первый слот** должен быть не раньше чем через 15 минут. Иначе скрипт остановится — возьмите `--start` позже.
* **`--dry`** ничего не загружает и ничего не пишет. В YouTube не ходит, поэтому канал не проверяет, а сверяется только с `published.csv`. Печатает расписание и тела всех запросов.
* **Ошибка загрузки** (квота, сеть, отказ API) останавливает пачку. Всё, что уже загружено, к этому моменту записано в `published.csv`. Если запустить ту же команду ещё раз, она продолжит с оставшихся выпусков, выложенное пропустит, а занятые им дни в расписании обойдёт.

**Один ролик:**

```
py publish_baby.py serious_lecture --at "2026-09-30 19:30"    запланировать (время МСК)
py publish_baby.py serious_lecture --now                       опубликовать сразу
py publish_baby.py serious_lecture --at "..." --dry            показать тело запроса
```

Одиночная выкладка тоже отказывается выкладывать то, что уже есть в `published.csv` или на канале, и тоже дописывает `published.csv`.

**`stats/baby/published.csv`** — одна строка на каждый загруженный ролик:

| колонка | что в ней |
|---|---|
| `name` | завязка |
| `video_id` | id ролика |
| `publish_at_utc` | время публикации в UTC |
| `at` | когда загружен, UTC |

Строка пишется сразу после загрузки ролика. Чтобы выложить ролик заново, удалите его строку из файла и сам ролик с канала.

## Что вживую не проверено

Канала ещё нет, поэтому трекер проверен только офлайн-тестами (`tests/test_track_baby.py`)
на подменных ответах API:

* **Показы и CTR.** Имена метрик (`videoThumbnailImpressions`, `videoThumbnailImpressionsClickRate`)
  взяты из документации Analytics API, живым запросом не проверены. Если API их не примет,
  колонки `impressions` и `ctr` останутся пустыми, в логе будет «показы/CTR недоступны»,
  остальное запишется. Для шортсов главная лента («показан / пролистан») в API, насколько
  известно, не отдаётся вовсе.
* **Задержка Analytics.** Досмотр и подписки в Analytics приходят с опозданием на 1–3 дня,
  поэтому у свежих роликов в первых снимках эти колонки пустые или занижены. Просмотры, лайки
  и комментарии (Data API) — почти в реальном времени.
* **Выкладка.** `publish_baby.py` проверен офлайн-тестами (`tests/test_publish_baby.py`) с подменным
  клиентом и холостым `--dry` на настоящих `shorts.json` и `CHANNEL_PACK.md`. Живой загрузки на канал
  ещё не было. Сколько роликов подряд YouTube примет за сутки, тоже не проверено: если загрузку
  остановит лимит, пачка остановится с сообщением, а завтра её продолжит та же команда.
