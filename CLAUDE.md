# auto-shorts — контекст для агента

Три канала коротких роликов с фактами: **en**, **es**, **pt**. Тема ->
сценарий -> стоковые клипы -> озвучка -> видео -> выгрузка на YouTube и
дальше по площадкам.

Здесь записано, **что чем запускать**. Расчёт на то, что за работу сядет
другой помощник и ему не придётся восстанавливать это по переписке.

---

## Главное: работает оно НЕ на этой машине

Ежедневная сборка идёт в **GitHub Actions**, по расписанию, а не руками.
Локально запускают только пробы. Отсюда два следствия, которые дороже всего
обходятся, если о них не знать:

* **Ключи живут в секретах репозитория**, а не в файлах. `ANTHROPIC_API_KEY`,
  `PEXELS_API_KEY`, `YT_*`, `IG_*`, `TIKTOK_*`, `PINTEREST_*`, `TELEGRAM_*` —
  полный список видно в `env:` любого из `daily*.yml`.
* **Канал выбирается переменной `CHANNEL`** (`en` по умолчанию, ещё `es`,
  `pt`). Она же разводит все файлы состояния: `queue_en.json`,
  `video_history_es.json`, `dropoff_stats_pt.json` и прочие.

Потоки в `.github/workflows`:

| файл | что делает |
|---|---|
| `daily.yml`, `daily-es.yml`, `daily-pt.yml` | ежедневный ролик на канал |
| `watchdog*.yml` | сторож: проверяет, что ролик вышел |
| `weekly-longform*.yml` | длинный ролик раз в неделю |
| `weekly-series*.yml` | серии |
| `monthly-compilation.yml` | месячная сборка |
| `monthly-insights.yml`, `weekly-report.yml` | отчёты |
| `discover-niche.yml`, `monthly-topic-discovery.yml` | поиск тем |
| `prepare-batch.yml` | предзаготовка сценариев через Batch API |
| `recycle-winners.yml` | переиспользование удачных |
| `token-health.yml` | проверка живости токенов |

Точка входа всюду одна: `src/pipeline.py`, запускается из каталога `src`.

## Локальные запуски

```
cd C:\work\auto-shorts\src

py test_local.py            полный прогон БЕЗ выгрузки
py rerender.py              пересобрать видео из сохранённого сюжета
CHANNEL=es py test_local.py другой канал
```

**Разница между ними — деньги, и это главное правило проекта.**

`test_local.py` идёт целиком: сочиняет сценарий (платный запрос к модели),
качает клипы, озвучивает, собирает видео. Складывает всё на рабочий стол в
`auto-shorts-test`, включая `meta.json`.

`rerender.py` берёт готовый `meta.json` и пересобирает ТОЛЬКО видео — без
единого платного запроса.

Отсюда:

* правил `build_video.py` (вёрстка, подписи, переходы) — **`rerender.py`**,
  бесплатно;
* правил сценарий, подбор клипов или озвучку — **`test_local.py`**, платно.

Гонять `test_local.py` ради проверки шрифта — выброшенные деньги.

## Грабли, уже оплаченные

**Свой OAuth-клиент на каждый канал.** У Google предел — 50 живых токенов на
пару `client_id` + аккаунт, и общий `client_id` вытеснял чужие токены. Поэтому
в потоках есть `YT_CLIENT_ID_EN` и `YT_CLIENT_SECRET_EN` отдельно от общих.
Если секрет не заведён, `_client_pair()` падает обратно на общие.

**Очередь сценариев коммитится обратно в репозиторий.** `pipeline.py` может
взять готовый сценарий из `queue_en.json` и вычеркнуть его локально; без
коммита обратно следующий запуск снова увидел бы несдвинутую очередь из git.
Коммит стоит с `if: always()`, чтобы слот не выдавался повторно даже при
частичном сбое.

**Перезапуск упавшего из-за конфликта задания через `gh run rerun` не
работает** — он берёт устаревший SHA. Запускать заново надо
`gh workflow run <файл>`.

**Windows-консоль в cp1251 роняет печать заголовков** с диакритикой уже ПОСЛЕ
платной генерации сценария. `test_local.py` поэтому переключает вывод на utf-8
первым делом.

**ImageMagick в Actions требует правки политики** — строка с `pattern="@*"`
удаляется перед прогоном, иначе он отказывается читать текст подписей из
файла.

## Что лежит рядом

* `telegram-bot/` — свой README, отдельная служба.
* `docs/` — только `privacy.html` и `tos.html` для страниц согласия OAuth.
* `SETUP_ES.md` — заметки по заведению испанского канала.
* Файлы `*_en.json`, `*_es.json`, `*_pt.json` в корне — состояние каналов
  (очередь, история, статистика удержания и зацепок). Руками не править:
  их пишет и коммитит сам поток.
