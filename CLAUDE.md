# auto-shorts — контекст для агента

Каналы коротких роликов с фактами: **en**, **es**, **pt**. Тема -> сценарий ->
стоковые клипы -> озвучка -> видео -> выгрузка на YouTube и дальше по площадкам.

⚠️ **Сейчас живой только `es`.** EN и PT поставлены на паузу 2026-08-21: их
воркфлоу отключены через `gh workflow disable`, а внутри общих воркфлоу
(prepare-batch, discover-niche, monthly-*) их шаги стоят под `if: false`.
Причина — данные: ES обгонял оба по всем метрикам, EN и PT месяцами стояли на
плато. EN держат «прогретым» под будущий репёрпоуз, не закрывают. Возобновить:
`gh workflow enable <файл>` + снять `if: false` (правки помечены датой в файлах).

Здесь записано, **что чем запускать**. Расчёт на то, что за работу сядет
другой помощник и ему не придётся восстанавливать это по переписке.

## Главное: работает оно НЕ на этой машине

Ежедневная сборка идёт в **GitHub Actions**, по расписанию, а не руками.
Локально запускают только пробы. Отсюда два следствия, которые дороже всего
обходятся, если о них не знать:

* **Ключи живут в секретах репозитория**, а не в файлах. `ANTHROPIC_API_KEY`,
  `PEXELS_API_KEY`, `YT_*`, `IG_*`, `TIKTOK_*`, `PINTEREST_*`, `TELEGRAM_*` —
  полный список видно в `env:` любого из `daily*.yml`.
* **Канал выбирается переменной `CHANNEL`** (`en` по умолчанию, ещё `es`,
  `pt`). Она же разводит все файлы состояния: `queue_en.json`,
  `video_history_es.json`, `dropoff_stats_pt.json` и прочие.

Потоки в `.github/workflows`:

| файл | что делает |
|---|---|
| `daily.yml`, `daily-es.yml`, `daily-pt.yml` | ежедневный ролик на канал |
| `watchdog*.yml` | сторож: проверяет, что ролик вышел |
| `weekly-longform*.yml` | длинный ролик раз в неделю |
| `weekly-series*.yml` | серии |
| `monthly-compilation.yml` | месячная сборка |
| `monthly-insights.yml`, `weekly-report.yml` | отчёты |
| `discover-niche.yml`, `monthly-topic-discovery.yml` | поиск тем |
| `prepare-batch.yml` | предзаготовка сценариев через Batch API |
| `recycle-winners.yml` | переиспользование удачных |
| `token-health.yml` | проверка живости токенов |

Отключены на 2026-09-07: всё EN/PT-специфичное, `recycle-winners.yml` (кросс-
опыление EN↔ES, без EN бессмысленно) и `monthly-compilation.yml` (месячные
сборки набирали 10-91 просмотр). Актуальный список всегда в `gh workflow list --all`.

Точка входа всюду одна: `src/pipeline.py`, запускается из каталога `src`.

### Расписание живёт в ТРЁХ местах, и их легко рассинхронить

`daily*.yml` и `weekly-longform*.yml` **не запускаются GitHub-кроном** — родной
cron оттуда убран (опаздывал и плодил дубли). Их дёргает снаружи
**cron-job.org** через `workflow_dispatch`. Поэтому при смене слотов править
надо все три места, иначе слот просто не выстрелит:

1. `config.py` -> `daily_slots_utc` (канальный конфиг, время в **UTC**);
2. `.github/workflows/watchdog-<канал>.yml` -> `cron:` (сторож, +15 мин к слоту);
3. **cron-job.org**, папка канала (`eng` / `esp` / `port`) — задания в
   часовом поясе **Europe/Moscow (UTC+3)**, то есть время там = UTC + 3.

Задания там называются по МСК-времени (`ES-2000` = 20:17 МСК = 17:17 UTC), но
имена местами врут после переносов — сверяться надо по crontab-выражению в самом
задании, а не по названию. Новое задание удобнее не создавать с нуля, а
клонировать существующее (ДЕЙСТВИЯ -> Клонировать): токен GitHub в заголовках
переносится сам, руками его вводить не нужно. Ненужные задания в этом аккаунте
принято **выключать тумблером, а не удалять** (все EN/PT так и лежат).

Слоты ES на 2026-09-07: 13:17 / 17:17 / 20:17 / 22:17 / 00:17 UTC.

## Локальные запуски

```
cd C:\work\auto-shorts\src

py test_local.py            полный прогон БЕЗ выгрузки
py rerender.py              пересобрать видео из сохранённого сюжета
CHANNEL=es py test_local.py другой канал
```

**Разница между ними — деньги, и это главное правило проекта.**

`test_local.py` идёт целиком: сочиняет сценарий (платный запрос к модели),
качает клипы, озвучивает, собирает видео. Складывает всё на рабочий стол в
`auto-shorts-test`, включая `meta.json`.

`rerender.py` берёт готовый `meta.json` и пересобирает ТОЛЬКО видео — без
единого платного запроса.

Отсюда:

* правил `build_video.py` (вёрстка, подписи, переходы) — **`rerender.py`**,
  бесплатно;
* правил сценарий, подбор клипов или озвучку — **`test_local.py`**, платно.

Гонять `test_local.py` ради проверки шрифта — выброшенные деньги.

## Грабли, уже оплаченные

**Свой OAuth-клиент на каждый канал.** У Google предел — 50 живых токенов на
пару `client_id` + аккаунт, и общий `client_id` вытеснял чужие токены. Поэтому
в потоках есть `YT_CLIENT_ID_EN` и `YT_CLIENT_SECRET_EN` отдельно от общих.
Если секрет не заведён, `_client_pair()` падает обратно на общие.

**Очередь сценариев коммитится обратно в репозиторий.** `pipeline.py` может
взять готовый сценарий из `queue_en.json` и вычеркнуть его локально; без
коммита обратно следующий запуск снова увидел бы несдвинутую очередь из git.
Коммит стоит с `if: always()`, чтобы слот не выдавался повторно даже при
частичном сбое.

**Перезапуск упавшего из-за конфликта задания через `gh run rerun` не
работает** — он берёт устаревший SHA. Запускать заново надо
`gh workflow run <файл>`.

**Windows-консоль в cp1251 роняет печать заголовков** с диакритикой уже ПОСЛЕ
платной генерации сценария. `test_local.py` поэтому переключает вывод на utf-8
первым делом.

**ImageMagick в Actions требует правки политики** — строка с `pattern="@*"`
удаляется перед прогоном, иначе он отказывается читать текст подписей из
файла.

**Квота YouTube: лимит 10 000/день, но ролик стоит ~606 единиц, а не 2150.**
С 03.07.2026 `videos.insert` вынесен в отдельный бакет и стоит 1 ед. вместо 1600
(там же `search.list`). Основной едок — `captions.insert` 400, то есть две трети.
ES на 5 слотах тратит ~3 030 из 10 000. На этих цифрах уже дважды ошибались в
обе стороны (урезали субтитры «ради квоты», потом решили, что лимит подняли до
26 000) — **не делить наблюдаемый объём на предполагаемую цену вызова, а брать
стоимость из этого абзаца.**

**Локальный Pillow 9.5.0 роняет процесс (segfault, exit 139) на любом тексте с
пробелом.** Молча, без трейсбека, поэтому выглядит как падение совсем другого
участка. В CI тот же пин работает — прод не трогать. Для локального превью
тумбы/подписей ставить рабочий Pillow изолированно:
`py -m pip install --target <tmp>/pil_new Pillow==10.4.0` и подкладывать через
`PYTHONPATH`. Заодно `import build_longform_video` тянет moviepy и тоже падает —
для превью тело функции удобнее выдернуть из файла текстом и `exec`-нуть.

**`video_history_<канал>.json` — НЕПОЛНЫЙ срез канала, не считать по нему доли.**
На ES было 304 ролика на канале, 211 записей в файле и 172 с метриками. Пишется
только с момента внедрения трекинга, плюс был баг с молчаливой потерей записей
до 18.07. Для анализа всего канала тянуть теги и просмотры напрямую из YouTube
API (playlistItems -> videos.list): вся разметка лежит в тегах `topic-`, `tone-`,
`opener-`, `hook-`, `format-`.

**Отбор кадров может остановить канал целиком — смотреть `recovery_<канал>.json`.**
Эпизод (сценарий + одобренные кадры) сохраняется в этот файл, если прогон не набрал
сцен, и следующий прогон его возобновляет. 2026-09-12 сценарий застрял на 5/6 сцен и
8 попыток подряд падал одинаково — больше суток без роликов. Теперь публикация идёт от
порога `min_publish_scenes` (4, настраивается в CFG), а эпизод ниже порога бросается
после `max_episode_attempts` (3). Симптом: в `gh run list` серия failure, в файле
`pending` с одним и тем же `created` у многих записей `attempts`. Если что-то снова
застрянет — не править файл руками, а разбираться, почему порог недостижим.

Отчёт — `docs/AUDIT_2026-09.md`: прогоны за 30 дней, причины падений, расходы, выводы по данным ES,

Правки того же PR: повтор загрузки на YouTube (`upload_youtube.resumable_upload`), сверка эпизода,

push при сохранении состояния (`scripts/git_persist.sh`, в `daily-es`/`watchdog-es`/`track-baby`).
Тесты: `pip install -r requirements-dev.txt`, затем `python -m pytest tests` (в CI не гоняются).

Трекер нового канала (англоязычная серия «малышка и щенок» из репозитория AI) — `src/track_baby.py`
(снимок раз в день в `stats/baby/daily.csv` и `videos.csv`), `src/track_baby_report.py` (сводка по
типам завязок в `stats/baby/weekly.md` по понедельникам), поток `track-baby.yml`. **Выключен, пока
нет секрета `YT_TOKEN_BABY`**: поток выходит зелёным с «канал не подключён». Подключить:
`py src/get_youtube_token.py baby`, пошагово — `docs/SETUP_BABY.md`. Ролик с завязкой связывает
тег `s-<name>` (или строка в `stats/baby/mapping.csv`). Выкладка — `src/publish_baby.py`: один ролик или пачка
`--plan FROM-TO --start ГГГГ-ММ-ДД` по расписанию. Выложенное пишется в `stats/baby/published.csv`, повторно не уходит.
Команды — в `docs/SETUP_BABY.md`, раздел «Выкладка».
